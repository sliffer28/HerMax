1. Executive Summary & Product Overview

1.1 Mission & Vision

HERMAX (formerly HermesAI) is an advanced, privacy-first Android AI client engineered to provide a seamless, ChatGPT-grade mobile experience while preserving absolute user sovereignty over artificial intelligence model access. Its guiding principle is “Your AI. Your Control.”

Unlike conventional mobile AI applications that bind the user to a single proprietary subscription or route all traffic through centralized third-party servers, HERMAX bridges two worlds:

  • Zero-Cloud Local AI Execution: Direct LAN connectivity to local agent runtimes (Hermes Agent running on the user's desktop/server) and local Ollama instances on private networks.
  • Direct-to-Cloud LLM Provider Integration: Native, direct client-to-cloud connections to major AI providers (Google AI Studio, OpenAI, Anthropic Claude, OpenRouter, Ollama Cloud, NVIDIA NIM, and custom OpenAI-compatible endpoints) using the user's own API keys stored securely in the hardware-backed Android Keystore.

1.2 Core Architectural Principles

  • Zero Telemetry / Zero Proxy: All network requests travel directly from the Android phone to the designated host (either local IP or cloud provider API). No intermediate proxy server is utilized.
  • Hardware-Grade Keystore Security: API keys are encrypted at rest using AES-256-GCM authenticated encryption backed by the Android hardware Keystore.
  • Streaming-First Architecture: Built from the ground up for low-latency token streaming using Server-Sent Events (SSE) and reactive Kotlin Coroutines Flow.
  • Resilient Clean UI: Full CommonMark and GitHub Flavored Markdown (GFM) renderer supporting syntax-highlighted code blocks, crash-proof responsive tables with horizontal scrolling, and automatic HTML sanitization.

4. System Architecture & Component Interactions

4.1 Architectural Pattern: Clean MVVM with Unified Provider Routing

HERMAX implements a Model-View-ViewModel (MVVM) architecture augmented by Clean Architecture principles:

  • UI Layer (Compose Composables): Passive, declarative screens that observe StateFlow objects emitted by ViewModels and transmit user intents via simple function callbacks.
  • ViewModel Layer (State Holder & Coordinators): Lifecycle-aware ViewModels (e.g. ChatViewModel, SettingsViewModel, ThemeViewModel) managing asynchronous operations, state reduction, and database synchronization.
  • Domain Layer (Contracts & Models): Framework-independent interfaces (AIProvider, ConversationRepository) and pure domain data classes (Message, UnifiedModel, ProviderConfig).
  • Data Layer (Implementations & Security): Concrete implementations interacting with disk (Room SQLite database, Preferences DataStore, Android Keystore EncryptedSharedPreferences) and network (Retrofit, OkHttp SSE).

5. End-to-End Chat Request & Streaming Lifecycle

Understanding the exact path of a message from the instant the user taps the send button to the moment the styled response is rendered on the mobile display is fundamental for maintaining HERMAX.

5.1 Step-by-Step Execution Sequence

  1. User Action (ChatComposer.kt): The user types a message or attaches files. When tapping the send arrow, ChatComposer executes onSendMessage(text).
  2. Draft Persistence Guard (ChatViewModel.kt): To prevent creating empty, cluttering conversations when navigating back and forth, the conversation record in the Room database is only created upon sending the first message. If _isNewConversation is true, a new ConversationEntity is generated, titled with the prompt preview, and inserted into HermesDatabase.
  3. Attachment Ingestion: If text files are attached, FileAttachmentHelper extracts their text and formats them as markdown context blocks. If binary files (images/PDFs) are sent to Hermes Agent, they are uploaded via hermesRepository.uploadFile().
  4. User Message Emission: A Message with role = USER and status = SENT is inserted into Room. The reactive Flow emitted by ConversationDao immediately pushes this message into _messages, rendering it in LazyColumn.
  5. Provider Resolution (AIProviderRegistry.kt): ChatViewModel.startStreaming() inspects headerState.value.selectedProvider. It queries aiProviderRegistry.getProvider(providerType) to retrieve the targeted provider instance (e.g. OllamaCloudProvider, OpenAIProvider, or HermesProvider).
  6. Credential Decryption: The provider instance calls secureStorage.getProviderConfig(providerType). The encrypted preferences string is decrypted using the hardware MasterKey, obtaining the API key and endpoint.
  7. HTTP Request Dispatch & SSE Connection: An HTTP POST request is assembled with headers (e.g. Authorization: Bearer [REDACTED]) and an SSE streaming listener is attached via EventSources.createFactory(cloudOkHttpClient).newEventSource(request, listener).
  8. Token Accumulation & Reactive State Update: As SSE chunks arrive (e.g. data: {"choices":[{"delta":{"content":"..."}}]}), the provider converts them to HermesEvent.Chunk(delta). ChatViewModel accumulates chunks into streamingContent and updates ChatUiState.
  9. Sanitization & AST Markdown Parsing: MessageBubble.kt passes the incoming stream into MarkdownContent → MarkdownRenderer. HtmlSanitizer normalizes any mixed HTML and protects table line breaks. The CommonMark parser constructs an AST.
  10. Native Compose Layout Rendering: The AST nodes are rendered into native Material 3 Composables: paragraphs, headings, syntax-highlighted code blocks, and MarkdownTable with horizontal scrolling.
  11. Stream Completion & Database Finalization: When the provider emits HermesEvent.Done, ChatViewModel creates a final Message with role = ASSISTANT and status = COMPLETED and writes it to Room. isStreaming is reset to false.

6.2 Custom Provider URL Normalization Protocol

Users connecting local servers (LM Studio, vLLM, LocalAI) often enter base URLs inconsistently (e.g. http://[REDACTED_IP]:8080 vs http://[REDACTED_IP]:8080/v1/). HERMAX implements strict URL normalization in domain/model/Providers.kt: 

fun normalizeOpenAiBaseUrl(raw: String): String {
    val trimmed = raw.trim().trimEnd('/')
    if (trimmed.isBlank()) return ""
    val withScheme = if (!trimmed.startsWith("http://", ignoreCase = true) && 
                         !trimmed.startsWith("https://", ignoreCase = true)) {
        "http://$trimmed"
    } else trimmed
    return if (withScheme.endsWith("/v1", ignoreCase = true)) {
        withScheme
    } else {
        "$withScheme/v1"
    }
}

7. Response Rendering Pipeline

The HERMAX Markdown rendering engine transforms raw streaming LLM output into publication-grade, mobile-optimized UI. It solves two critical industry problems:

  • Raw HTML & <br> Leakage: Models frequently output <br> tags inside Markdown table cells or lists because GFM specification does not allow multiline cells without breaks. HERMAX sanitizes and restores these as true line breaks.
  • Table Layout Crashing: Standard Jetpack Compose custom measure policies crash with IllegalStateException: measure() may only be called once if multi-pass measurement is attempted. HERMAX uses a crash-proof, calculated-width Column/Row architecture with contained horizontal scrolling.

7.1 Crash-Proof Table Implementation (MarkdownTable.kt)

Tables are laid out in a contained horizontal scroll container. Each column width is computed deterministically from the maximum character length of its cells (from 110.dp for short codes up to 300.dp for long descriptions). Because standard Compose Column and Row primitives are used with explicit column widths, columns align across headers and body rows with zero measure violations.

8. Security & Keystore Cryptographic Architecture

8.1 Android Keystore MasterKey Encryption

All sensitive credentials—including third-party provider API keys, custom server auth tokens, and session secrets—are stored using the Jetpack Security EncryptedSharedPreferences API backed by the hardware Android Keystore: 

private fun createSecurePrefs(context: Context): SharedPreferences {
    val masterKey = MasterKey.Builder(context)
        .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
        .build()
    return EncryptedSharedPreferences.create(
        context,
        "hermes_secure_prefs",
        masterKey,
        EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
        EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
    )
}
Security Invariants Enforced Across the Application
  • Hardware Keystore: Private encryption keys never leave the device's hardware security module (HSM) or Trusted Execution Environment (TEE).
  • Deterministic Key Hashing: Preference keys are encrypted with AES256_SIV (Synthetic Initialization Vector) to ensure keys cannot be correlated with known provider names by inspecting raw XML files.
  • Payload Encryption: Preference values are encrypted using authenticated AES256_GCM cipher suites.
  • No Server Relay: Direct cloud API keys are NEVER sent to the Hermes PC agent server; cloud requests exit the mobile device directly via TLS.

10.2 data/provider/AIProviderRegistry.kt

Purpose: Factory and router providing unified access to all 9 supported AI providers.

@Singleton
class AIProviderRegistry @Inject constructor(
    @Named("cloudOkHttpClient") private val cloudOkHttpClient: OkHttpClient,
    private val json: Json,
    private val secureStorage: SecureStorage,
    private val hermesRepository: HermesRepository
) {
    private val providers = mutableMapOf<AIProviderType, AIProvider>()

    init {
        providers[AIProviderType.HERMES_AGENT] = HermesProvider(hermesRepository)
        providers[AIProviderType.GOOGLE_AI] = GoogleAIProvider(cloudOkHttpClient, json, secureStorage)
        providers[AIProviderType.OPENROUTER] = OpenRouterProvider(cloudOkHttpClient, json, secureStorage)
        providers[AIProviderType.ANTHROPIC] = AnthropicProvider(cloudOkHttpClient, json, secureStorage)
        providers[AIProviderType.OPENAI] = OpenAIProvider(cloudOkHttpClient, json, secureStorage)
        providers[AIProviderType.OLLAMA] = OllamaProvider(cloudOkHttpClient, json, secureStorage)
        providers[AIProviderType.OLLAMA_CLOUD] = OllamaCloudProvider(cloudOkHttpClient, json, secureStorage)
        providers[AIProviderType.NVIDIA] = NvidiaProvider(cloudOkHttpClient, json, secureStorage)
        providers[AIProviderType.CUSTOM] = CustomProvider(cloudOkHttpClient, json, secureStorage)
    }

    fun getProvider(type: AIProviderType): AIProvider = 
        providers[type] ?: providers[AIProviderType.HERMES_AGENT]!!
}

13. Technical Glossary & Potential Extensions

13.1 Technical Glossary

  • SSE (Server-Sent Events): A unidirectional HTTP streaming protocol where the server pushes UTF-8 formatted text chunks over a persistent TCP connection using text/event-stream.
  • LLM (Large Language Model): Deep neural network models (e.g. Claude 3.5 Sonnet, GPT-4o, Llama 3) generating text tokens sequentially.
  • Android Keystore: A hardware-backed system service on Android devices that generates and stores cryptographic keys inside secure hardware (TEE/StrongBox) to prevent key extraction.
  • GFM (GitHub Flavored Markdown): Standard Markdown extension specification adding support for tables, task checklists, and strikethrough styling.
  • vLLM / LM Studio: Popular open-source local inference engines that host AI models locally while exposing OpenAI-compatible /v1/chat/completions endpoints.

13.2 Potential Future Extensions (Not Currently Implemented)

  • On-Device NPU Local Inference: Integration with Google MediaPipe or ONNX Runtime to execute lightweight 1B-3B quantized models directly on the mobile device processor.
  • Multi-Modal Audio Streaming: Support for bi-directional WebRTC audio streaming to engage in real-time voice conversations.
  • Encrypted Conversation Export: Exporting conversation databases into password-protected AES-256 backup archives.
